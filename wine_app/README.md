# Винная подборка — ДЗ-3

Приложение оценивает вероятность экспертной оценки вина не ниже 7 и показывает,
как порог меняет подборку. Вызовы методов сверены с официальной документацией библиотек.

Для вёрстки веб-интерфейса приложения использовался Codex.

## Запуск

Проверено на **Python 3.12.14**. Версии зависимостей зафиксированы в `requirements.txt`.

Из папки `wine_app`:

```bash
python -m venv .venv
```

Активировать окружение в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Или в macOS/Linux:

```bash
source .venv/bin/activate
```

Затем:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Из корня учебного репозитория можно запустить
`python -m streamlit run homework/hw_3/wine_app/app.py`.
Из корня отдельного репозитория `ml_hse_3_task`:
`python -m streamlit run wine_app/app.py`.
Файлы загружаются относительно `Path(__file__).resolve().parent`, поэтому текущая
папка запуска не влияет на поиск модели и данных.

## Что находится в папке

- `app.py` — четыре вкладки приложения.
- `model.joblib` — весь обученный пайплайн StandardScaler + LogisticRegression.
- `config.json` — порог, выбранный по валидации для максимального precision при recall ≥ 0.7.
- `test.csv` — отложенные данные с колонкой `target`, только для демонстрации метрик.
- `requirements.txt` — проверенные версии библиотек.

Модель обучается в `HW3_MMDA.ipynb`. Для воспроизведения ноутбука нужны также
`Data/wine_quality.csv` и эта папка `wine_app` рядом с ноутбуком. Приложение модель не обучает.
Перед разделением удалены полные дубликаты; масштабирование обучается только на train.
Порог выбирается по validation, после чего пайплайн переобучается на всей train.
Пример корректного CSV можно скачать на вкладке пакетного предсказания.

## Кэширование (ответ на 4.5)

`st.cache_resource` хранит общий экземпляр модели на сервере: не нужно заново
десериализовать ее при каждом действии пользователя. Модель после загрузки не изменяется.
`st.cache_data` используется для таблицы и массива вероятностей и возвращает
копии данных. Вероятности на test от порога не зависят и вычисляются один раз;
при движении ползунка пересчитываются метки, матрица ошибок и метрики.
Параметр `_model` исключен из хеширования, а таблица X входит в ключ кэша.

Если вызвать `joblib.load` без декоратора, при каждом перезапуске скрипта файл
будет читаться и модель восстанавливаться заново. Это лишняя работа без изменения
предсказаний. После замены файла модели на работающем сервере нужно очистить кэш
или перезапустить приложение.
